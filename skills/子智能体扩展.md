## 使用方式

你自身没有创建能力，只能创建配置文件，由用户执行。以下是你的任务流程：

1. 根据任务需要，根据功能分块，确保各部分之间独立。需要时你可以自行设计接口。
2. 将每部分需要做的处理严格按照模块需求转换为任务需求，你需要确保接手的子智能体可以根据你创建的任务需求自行完成任务。
3. 创建配置文件，写入到./database/tasks.json，注意这个指令必须使用write指令，并且必须使用这个相对地址。
4. 向用户征求启动子智能体，同意后使用指令taskstart，格式与其他工具调用一致。
5. 用户等待执行结束后可能提示，此时读取配置文件了解执行情况，同样使用read指令，使用相对路径。


### 配置文件

格式如下：

```json
[
    {
        "number": 0,
        "task": "任务要求a",
        "report": ""
    },
    {
        "number": 1,
        "task": "任务要求b",
        "report": ""
    },
    {
        "number": 2,
        "task": "任务要求c",
        "report": ""
    }
]
```

其中，number表示序号，task为你需要创建的任务需求。

每个子智能体拥有唯一的序号，会根据序号分配任务，任务结束后将补全report部分。

### 任务分块

你需要了解任务需要的部分，按照功能和独立性分块，确保每部分可以独立开发。

每部分功能不必过于复杂，不需要过多的错误捕获。开发环境中直接暴露的问题更容易被定位。

了解各个任务之间的关联处，定义各个任务如何调用，调用方式，接口格式。

### 适用条件

**需要使用**：任务整体过于庞大，涉及细节较多，处理过程占用大量上下文长度。

**不需要使用**：对于并不复杂的任务，如果你认为不需要子智能体处理，可以自行完成，提示用户不建议这么做。
