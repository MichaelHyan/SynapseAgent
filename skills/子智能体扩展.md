---
name: sub agent
description: "创建子智能体，控制其执行任务，并查询其进程状态。"
---

## 使用方式

子智能体已集成进主程序，直接通过 `subagent` 工具调用即可。子智能体在**后台线程**中独立运行，不会阻塞你：调用后工具立即返回“已开始运行”的提示，你可以继续处理其他工作。

子智能体任务完成后的**任务简报（report）**会在后续某一轮、把消息发送给模型之前自动注入你的上下文（以 `[A]subagent report:` 开头，含任务序号）。你无需手动读取结果文件。

## 单任务

调用格式：`subagent [任务要求]`

子智能体拥有独立上下文与完整工具链，会自主完成任务。工具立即返回，后台运行。

## 多任务并行

调用格式：`subagent [JSON数组]`

数组中每个元素包含 `number`（序号）与 `task`（任务要求），多个子智能体会**并行**在后台执行，结束后各报告一并注入。JSON 需为单行紧凑格式，作为工具参数传递。

```json
[
    {"number": 0, "task": "任务要求a"},
    {"number": 1, "task": "任务要求b"}
]
```

## 查询子代理进程状态

调用格式：`subagent_status`（查询全部）或 `subagent_status [序号或ID]`（过滤）

由于子代理在后台异步运行，你可以随时查询其运行状态，包括：任务 ID、任务序号、状态（`running` 运行中 / `done` 已完成 / `error` 出错）、开始时间、耗时、任务摘要；已完成的还会附带报告摘要。

- 需要了解后台任务进展、确认是否完成、或排查异常时，使用该指令查询。
- 任务完成后的完整简报会自动注入，`subagent_status` 主要用于查看**运行中**或**历史**任务状态。

## 任务分块

你需要了解任务需要的部分，按照功能和独立性分块，确保每部分可以独立完成。

每部分功能不必过于复杂，不需要过多的错误捕获。开发环境中直接暴露的问题更容易被定位。

了解各个任务之间的关联处，定义各个任务如何调用，调用方式，接口格式。

## 适用条件

**需要使用**：任务整体过于庞大，涉及细节较多，处理过程占用大量上下文长度。

**不需要使用**：对于并不复杂的任务，如果你认为不需要子智能体处理，可以自行完成，提示用户不建议这么做。
